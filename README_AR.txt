# صدى العراق — الإصدار 3.0

حزمة Railway لتطبيق Sada Iraq. رقم الإصدار الظاهر للمستخدم هو **3.0**. معرّف البناء: `SADA-3.0-MOBILE-ADMIN-SERVICE-ORDER-PERF-20261031-R4`.

## تنظيم لوحة الإدارة
- **المستخدمون:** تبويبات بيانات الحساب، الشحن والخصم، كشف الرصيد وسجل المعاملات.
- **المدفوعات:** تبقى صفحة المدفوعات ومراجعة الشحنات المعتمدة؛ أزيلت صفحة إحصائيات الشحن المنفصلة.
- **خدمات الموقع:** إدارة الخدمات والأقسام والصور والأوصاف وربط المزودين والترتيب اليدوي أو حسب السعر في مساحة موحدة.
- **تحديث الخدمات والأسعار:** فحص الخدمات المعتمدة الموجودة فقط، تطبيق هامش الربح المحفوظ وعرض نتائج التحديث.
- **الطلبات والإشعارات والإعدادات:** الحفاظ على صفحات إدارة الطلبات وكشف الحالة، والإشعارات، وإعدادات الدفع وAPI وTelegram.
- **الدعم الفني:** يستخدم رابط واتساب المحفوظ في إعدادات المشروع.

## سياسة كتالوج المزود
- لا يستورد التحديث الدوري كتالوج المزود ولا ينشر خدمات جديدة تلقائياً.
- إضافة الخدمات الجديدة تتم يدوياً وبقرار مسؤول الموقع؛ التحديث التلقائي يقتصر على معرفات الخدمات المعتمدة الموجودة.
- لا تُحذف الخدمة بسبب timeout أو استجابة فارغة/ناقصة. لا تُعلّم الخدمة غير متاحة إلا بعد غيابها عن كتالوجين كاملين موثوقين متتاليين. يحتفظ النظام بسجل الخدمة والطلبات التاريخية.
- أدوات الاستيراد الجماعي القديمة أزيلت من واجهة الإدارة، كما تُرفض نقطة API القديمة ما لم تكن الإضافة خدمة واحدة تحمل موافقة المسؤول. إضافة Service ID المفردة تظل متاحة من داخل الإدارة. تبقى إعدادات الاتصال بالمزود وآلية إرسال الطلبات ضرورية للتشغيل.

## الطلبات والأرصدة
- يستعلم الخادم عن حالة الطلب بعد إنشاءه، ويحفظ حالة المزود ويربط رقم الطلب الداخلي بمعرف المزود.
- الطلبات غير المؤكدة والنشطة يعاد فحصها تلقائياً؛ انتهاء مهلة الاتصال لا يعني فشل الطلب ولا يؤدي وحده إلى رد الرصيد.
- رد الرصيد للحالات النهائية المؤكدة يستخدم حماية من التكرار وسجل معاملات.
- أرقام الطلبات العامة تبدأ من 3000، ومعرفات الخدمات الداخلية تستخدم أربع خانات مع المحافظة على المفاتيح التاريخية.
- إشعارات الطلبات لا تُعد مكتملة إلا بعد تأكيد الوصول إلى قناة Telegram الأساسية؛ نجاح الإرسال إلى نسخة احتياطية لا يوقف إعادة المحاولة للقناة.

## الحفاظ على البيانات
لم تُحذف حسابات المستخدمين أو حساب المدير أو الأرصدة أو الطلبات أو سجلات المعاملات أو Firebase أو إعدادات المزود/واتساب. إزالة واجهات فحص Firebase وقاعدة البيانات تخص لوحة الإدارة فقط؛ واجهات الخادم والربط الداخلي تبقى حسب الحاجة.

## النشر على Railway
1. استخدم Node.js 22 أو أحدث.
2. ارفع جميع الملفات إلى جذر المستودع؛ يجب وجود `server.js` و`package.json` و`railway.json` في الجذر.
3. استخدم Build Command: `npm run build` وStart Command: `npm start`.
4. اربط Railway Volume دائم واضبط `SADA_DATA_DIR=/data` حتى تبقى ملفات التشغيل والسجلات بعد إعادة النشر.
5. احتفظ بمتغيرات Firebase و`SESSION_SECRET` وبيانات مزود الخدمة وTelegram في Railway Variables أو مخزن الأسرار. لا تضف المفاتيح إلى ZIP أو المستودع.
6. نفّذ `npm test` قبل النشر، ثم اختبر طلباً صغيراً بحساب اختباري على بيئة آمنة.

## حدود الفحص
الاختبارات في هذه الحزمة محلية ومحاكاة للمزود وFirebase. لم يتم نشرها إلى Railway ولم تُجرَ معاملة إنتاجية فعلية؛ اختبار ما بعد النشر مطلوب للتأكد من بيانات اتصال المستخدم والمزود والقناة الحقيقية.


## تنظيم ملفات الوثائق
تقارير الإصدار الحالي تبقى في جذر المشروع: `SadaIraq_v3.0_QA_AR.md` و`RELEASE_NOTES_3.0_AR.md`. الوثائق التاريخية القديمة نُقلت إلى `docs/history/` و`docs/qa-history/` لتجنب الخلط بينها وبين الإصدار الحالي.

## تحسين مراقبة لوحة الإدارة
تُهيأ صفحات الإدارة عند فتح التطبيق والتنقل، وتُراقب إضافات عناصر القائمة الجانبية فقط. لا يوجد مراقب DOM شامل لكل لوحة الإدارة ولا مؤقت يعيد تهيئة الصفحات دورياً كل أربع ثوانٍ.
