صدى العراق — حزمة تشغيل خفيفة

الإصدار: 5.2

الملفات في هذه الحزمة مقتصرة على ملفات التشغيل والإعدادات الأساسية وملفات النشر.
تم حذف ملفات الاختبارات المنفصلة والتقارير التاريخية من نسخة النشر لتقليل حجم وعدد الملفات؛ هذا لا يحذف وظائف الموقع من server.js أو الواجهتين.

تشغيل Railway أو Render
1) استخدم Node.js 22 أو أحدث.
2) ثبّت الاعتمادات بواسطة npm install.
3) نفّذ npm test أو npm run build للفحص الأساسي.
4) شغّل npm start.
5) لا تغيّر Root Directory: يجب أن يكون المجلد الذي يحتوي server.js وpackage.json وrailway.json.

النشر على Netlify
- تحتفظ الحزمة بإعداد netlify.toml وملف netlify/functions/api.js وسكربت scripts/prepare-netlify.js.
- اربط المستودع أو استخدم Netlify CLI حتى تُبنى الدالة. رفع ملفات HTML وحدها لا يشغّل API.
- اضبط متغيرات البيئة السرية FIREBASE_DATABASE_URL وFIREBASE_SERVICE_ACCOUNT_JSON وSESSION_SECRET. لا تضع مفتاح حساب الخدمة في ملفات الواجهة.

Firebase والأمان
- إعدادات Firebase وقواعد البيانات محفوظة في config.json وdatabase.rules.json.
- admin-auth.json يحتوي بيانات تحقق الإدارة؛ لا تنشر المشروع في مستودع عام ولا تشارك الملف مع أي شخص.
- لا تضف ملفات Service Account أو مفاتيح API أو ملفات .env إلى ZIP.
- اضبط مساحة تخزين دائمة في الاستضافة إذا كنت تعتمد على الملفات المحلية والصور والبيانات التي لا تحفظ في Firebase.
- أنشئ نسخة احتياطية قبل أي ترقية. نجاح الاختبار المحلي لا يثبت وحده اتصال Firebase أو مزود الخدمات الحي بعد النشر.

التحديث المستقبلي
- سكربت scripts/bump-release.js يرفع رقم الإصدار ويحدّث علامات النسخة. بعد استخدامه نفّذ npm test وnpm run build وراجع تغييرات الملفات قبل النشر.

ملاحظة
هذه نسخة نشر خفيفة وليست حزمة تطوير كاملة؛ اختبارات المطور المنفصلة وسجلات الإصدارات القديمة أزيلت لتقليل عدد الملفات. احتفظ بنسخة التطوير الكاملة إذا احتجت إعادة تشغيل مجموعة الاختبارات الشاملة.
